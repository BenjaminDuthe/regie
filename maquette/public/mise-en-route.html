Première mise en route

Ce que voit quelqu'un qui vient de cloner le dépôt public et de lancer regie pour la première fois. Aucun secret n'est livré avec le code : tout se saisit ici.

Avant de démarrer

Trois commandes, aucune clé dans le dépôt
git clone https://github.com/BenjaminDuthe/regie cd regie && pnpm install cp .env.exemple .env # puis renseigner REGIE_MASTER_KEY pnpm start # http://localhost:4310

.env ne contient qu'une seule variable obligatoire : REGIE_MASTER_KEY, la clé qui chiffre tous les secrets au repos. Les clés d'API des réseaux ne s'écrivent jamais dans un fichier : elles se saisissent dans Paramètres, une fois regie démarrée.

Étape 3 — Mot de passe d'accès

Défini une seule fois, ici
12 caractères au minimum. Stocké haché, jamais en clair, jamais réaffiché.
Un seul utilisateur en V1 regie est une application mono-poste : un mot de passe, pas de comptes ni de rôles. Le second facteur est hors V1 — il est noté, pas oublié.

Ce que regie ne fait pas à votre place

  • ·
    Elle ne crée aucun compte de réseau social
    Les comptes existent déjà ; regie s'y connecte, c'est tout.
  • ·
    Elle n'écrit aucun texte
    Aucune IA en V1 hors MCP. Les légendes et les scènes viennent de vous, ou de Claude par MCP.
  • ·
    Elle ne capture jamais un compte réel
    La capture refuse de démarrer hors du compte de démonstration déclaré.

Aucun secret dans le dépôt

Le dépôt public ne contient ni clé, ni jeton, ni identifiant — seulement .env.exemple avec des valeurs vides. Une installation neuve démarre sans rien savoir de la vôtre.

Sauvegarde

Un seul dossier à copier : ./donnees. La restauration se teste — copier le dossier sur une machine vierge et relancer regie doit suffire.
