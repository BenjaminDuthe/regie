Comment regie est construit

Les grandes décisions techniques du studio de vidéos verticales, expliquées sans jargon. La référence exacte, pour qui code, est le socle ARCHITECTURE-SPINE.md (21 décisions, AD-1 à AD-21).

L'idée en une image

regie a un cœur qui sait tout du métier : qui a le droit de faire quoi, où en est chaque vidéo, ce qui reste du quota. Autour, des ateliers spécialisés font le travail lourd (transcrire, proposer un montage, fabriquer la vidéo, filmer une appli, publier). Ces ateliers ne savent rien des utilisateurs : ils prennent un travail dans une file d'attente, le font, rendent le résultat.

Trois portes d'entrée — l'interface, Claude et l'API — appellent exactement les mêmes fonctions du cœur. Une règle n'est donc écrite qu'une fois : ce que l'interface refuse, Claude le refuse aussi, pour la même raison et avec le même message.

Le parcours d'une vidéo

  1. Envoi des rushes. Le téléphone envoie les fichiers par morceaux ; une coupure de réseau reprend là où elle s'était arrêtée. Le quota est réservé avant le transfert : pas de 20 Go envoyés pour rien.
  2. Analyse. Un atelier mesure durée, son, netteté, puis la transcription note chaque mot avec son instant.
  3. Proposition. Le modèle de langage local propose coupes, accroche et textes. C'est le cœur qui en fait un montage : une description de la vidéo en JSON, jamais modifiée ensuite. Chaque correction crée une nouvelle version ; l'ancienne reste.
  4. Relecture. L'aperçu se joue dans le navigateur et applique les corrections tout de suite, sans attendre un nouveau calcul.
  5. Gardée. Quand la vidéo est gardée, le fichier final est fabriqué sur la carte graphique, après contrôle des « gardes » (texte lisible, zones sûres, durées permises par chaque réseau). Une garde ne se contourne pas.
  6. Publication. À l'heure dite, la vidéo part vers Instagram, Facebook, TikTok ou YouTube. Elle ne part jamais deux fois : si un doute existe sur un envoi interrompu, regie le signale au lieu de renvoyer.

Ce qui protège les inscrits

Chacun chez soi. La base elle-même filtre chaque ligne par espace : même une requête mal écrite ne montre rien d'un autre. L'administrateur ne voit pas les contenus.
Secrets au coffre. Clés et connexions aux réseaux sont chiffrées ; la clé maîtresse n'est jamais sauvegardée avec elles. Aucun secret ne passe par Claude ni par l'API.
Capture enfermée. Filmer une appli web se fait dans une machine séparée, avec un navigateur jetable qui ne peut joindre que les sites dont on a prouvé la propriété.
Traces infalsifiables. Chaque action est inscrite dans un journal chaîné : une modification après coup se voit.

Où ça tourne

Sur le serveur Proxmox de Benjamin, dans deux conteneurs système (LXC) : regie pour le cœur, la base et les ateliers, regie-capture pour la capture, isolé du reste. La carte Intel Arc B570 est partagée avec Tdarr ; regie n'y lance qu'un travail lourd à la fois, et chaque atelier libère la mémoire de la carte en terminant. Forgejo construit et teste chaque version ; Uptime Kuma prévient en cas de panne, de disque plein ou de sauvegarde manquée.

Toute l'IA est locale : Whisper pour la transcription, un modèle libre de 8 à 9 milliards de paramètres pour les propositions, une voix sous licence libre. Aucune donnée ne part vers une IA en nuage. Tout est libre et gratuit.

Connecter son Claude

Chaque inscrit branche son propre Claude sur regie par un bouton « Se connecter » (OAuth), comme pour n'importe quel connecteur. Il choisit l'espace et ce que Claude a le droit de faire. Quelques actions sensibles restent réservées à l'interface : créer une clé, gérer les membres, connecter un réseau social, supprimer un compte.
